# Backend integration

Coordinator owns workspace membership and daemon/JcodeBridge integration. Add `crates/ohagent-aaas` to workspace members before `cargo test -p ohagent-aaas`. Backend source changes are confined to this crate. The coordinator owns the workspace lockfile generated by Cargo dependency resolution.

## Public Rust API

```rust
pub struct Config { pub database_path: PathBuf, pub oidc: Option<OidcConfig> }
pub struct OidcConfig { pub issuer: String, pub audience: String, pub client_id: String }
pub async fn State::open(config: Config, runtime: Option<Arc<dyn Runtime>>) -> Result<State, BackendError>;
pub fn router(state: State) -> axum::Router; // full /api/aaas paths, merge rather than nest again
#[async_trait::async_trait]
pub trait Runtime: Send + Sync {
    async fn execute(&self, execution: RunExecution, sink: EventSink) -> Result<(), String>;
}
```

`RunExecution` has `tenant_id: String`, `run_id: String`, `process: Process`, `producer_epoch: String`. `Process` has `id: String`, `version: u64`, `input: ProcessInput`. Use `execution.process.input.{title,goal,expected_result,materials}`. JSON serializes these process input fields flat for the shared HTTP contract.

`EventSink` is cloneable. Its synchronous methods return `Result<_, BackendError>` except `is_cancelled`:

- `dispatch(role: &str) -> Result<(), BackendError>` MUST commit before invoking/creating the recipient runtime. Duplicate dispatch is rejected.
- `start_instance(role: &str, instance_id: &str) -> Result<Task, BackendError>` MUST run only after an actual Jcode session exists. It requires prior durable dispatch and all incoming graph predecessors completed. There is deliberately no method that fabricates an instance ID.
- `complete_task(task_id: &str, summary: &str) -> Result<(), BackendError>` requires a running task. The returned `Task.id` is the argument, not role or instance ID. Summaries are bounded to 2,000 bytes and must be safe user-facing summaries, never raw reasoning, prompts or tool arguments.
- `complete(artifact: &str) -> Result<(), BackendError>` requires all four actual tasks completed, no cancellation request and a nonempty bounded artifact. Independent deterministic structural verification checks UTF-8 text length and forbidden controls. It does NOT certify factual accuracy. Artifact storage, `artifact.verified`, `run.completed` and snapshot updates share one transaction.
- `fail(code: &str) -> Result<(), BackendError>` intentionally normalizes arbitrary adapter errors to `runtime_failed`, with no raw error disclosure.
- `is_cancelled() -> bool` is cooperative polling, true for requested cancellation, terminal states or unavailable storage.
- `confirm_cancelled() -> Result<(), BackendError>` MUST be called only after the engine has confirmed termination. Until then the run remains `cancellation_requested`. A producer exiting without confirmation becomes `interrupted`, never falsely `cancelled`.

All producer writes enforce the stored epoch, terminal status and cancellation fence transactionally. The pilot roles are `coordinator`, `analyst`, `evidence_checker`, and `reviewer`. New runs contain exactly four tasks and four directed edges: coordinator to analyst, coordinator to evidence_checker, analyst to reviewer, and evidence_checker to reviewer. Both `dispatch` and `start_instance` require every incoming predecessor to be completed, based on stored edges rather than task array order. After coordinator completion the adapter may dispatch and start analyst and evidence_checker concurrently, using distinct real Jcode sessions. Reviewer cannot dispatch or start until both branches complete. Each recipient still requires its own durable dispatch before start. Existing persisted runs retain their stored topology and are reconciled on startup, not rewritten. `dispatch` persists the edge handoff before recipient invocation. Do not create parallel-looking fake agents. JcodeBridge remains the sole model/tool executor. The backend never executes models.

Execution is bounded to eight concurrent jobs and 300 seconds per job. At timeout the execution future is aborted and durable state is interrupted/fenced. Adapter cancellation/drop handling must terminate its actual Jcode session/tools. The backend cannot guarantee termination of an external engine that ignores dropped futures. A normal producer exit without durable completion is failed. No automatic retry/reexecution occurs.

## Auth and HTTP

OIDC metadata is fetched over HTTPS using reqwest from configured issuer discovery, issuer matched exactly, no redirects and bounded metadata/JWKS bodies. Configure `audience` as the accepted API resource audience, distinct from public browser `client_id` when appropriate. JWKS validates asymmetric JWT signatures, issuer, audience, expiry, not-before, signed subject and intended signing key use/algorithm. Keys refresh every five minutes, unknown key IDs fail closed until refresh. No token, secret or raw JWT is logged or persisted.

`State::open` returns an error for invalid/unreachable configured discovery. Missing OIDC configuration opens a closed API whose public config is `{auth:null,pilot_available:false}`. Missing runtime rejects run creation. All tenant identity comes from SHA256(issuer + NUL + signed sub). Browser tenant headers are ignored and tenant input fields are rejected. This is one workspace per OIDC principal for MVP, not organization membership management.

Merge `router(state)` outside the existing operator-key middleware. It contains full `/api/aaas/...` routes. `/config` is unauthenticated and returns only public PKCE configuration. API errors are `{error:{code:string}}` with safe codes suitable for localized frontend messages. All responses are `Cache-Control: no-store`. No development login route, env-based auth bypass or public test injection exists. Injectable authorizers are private and constructed only by Rust unit tests.

SSE is fetched with Authorization, never query-string tokens. SSE event name is `journal`, id is the durable `run_seq`, data is the JSON contract envelope. Its allowlisted payload contains `status`, `version`, `snapshot` (Run only, never process materials, model prompts, tools or reasoning). Reducers can replace with `payload.snapshot` after checking the sequence/watermark. Reauthorization occurs before EVERY batch, not just connection start. Maximum batch is 64 journal entries, maximum simultaneous streams is 64, transport is pull/backpressure driven, polling is 500ms with 10s heartbeat. Streams close after terminal watermark. Stream auth failure emits `auth_required` and closes. Initial invalid/expired cursors return HTTP 409 with `reset_required`, later retention/cursor failures emit the same SSE event and close. Fetch the current snapshot and reconnect after its watermark. Journal entries are retained without pruning in this MVP. Expired-cursor handling is tested using labelled retention fixtures.

Artifact reads are tenant-authorized and returned as a text/markdown attachment, never a public path. List endpoints return at most 100 entries. Incoming request bodies, process fields, idempotency keys, tokens and runtime output fields are bounded.

## Persistence and startup

SQLite is the only database dependency. The file uses WAL, a five-second busy timeout, tenant-qualified composite keys and immediate transactions for mutation. Create snapshots, idempotency key payload hashes and first journal records are atomic. Process versions are immutable and pinned when the run is created. Replay reads stored journal entries only and never schedules commands.

On open, incomplete runs are transactionally marked `interrupted`, their remaining tasks are failed with `runtime_interrupted`, an interruption event is recorded and producer epochs are replaced. Existing idempotency keys continue returning the same interrupted run, not a fresh execution. This pilot assumes a single active daemon owner of a database file. A second open reconciles/fences prior producers rather than implementing multi-node leasing.

## Validation boundaries

Rust tests use real temporary on-disk SQLite and the actual axum router. Runtime and identity fixtures are explicitly test-only. Crypto tests generate ephemeral Ed25519 keys in memory, validating actual signed JWTs without storing credentials. These checks do not certify a live OIDC deployment or the coordinator's real JcodeBridge adapter. The coordinator must validate that separate integration and real pilot workflow. `fixture_dag_parallel_branches_merge_only_after_both_complete` uses concurrent test threads with explicitly labelled fixture session IDs, verifies two simultaneously running branches in durable snapshots and journal replay, exercises both branch completion orders and the reviewer merge fence, and reverses task array order to reject sequential-prefix readiness. `fixture_dag_restart_fences_both_running_branches_without_reexecution` checks interruption of both branches, stale producer fencing and stable idempotent replay across repeated opens. These are fixture-runtime/backend acceptance tests, not real E2E or evidence of model execution.
